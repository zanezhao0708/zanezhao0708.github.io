开源 PaperMind：用中文问英文论文的 RAG 问答系统

发布于 2026-08-17

做科研的同学大概都有过这样的经历：arXiv 每天几十篇新论文涌出来，英文原文啃起来慢；读到第三篇的时候，第一篇里某个方法的细节已经记不清了，翻回去找又要在几十页 PDF 里大海捞针。

这段时间我开源了一个小项目 PaperMind——面向计算机视觉异常检测（Industrial Anomaly Detection）领域的论文 RAG 问答系统。它解决两件事：用中文直接问英文论文，以及每天自动跟踪领域最新进展。这篇文章记录一下它的设计思路、关键技术决策和实测数据。

一、PaperMind 是什么

一句话：把一个领域的论文库变成一个可用中文提问、回答带引用标注的知识库。

上传论文 PDF（内置脚本一键下载 PatchCore / PaDiM / SPADE / CutPaste / DRAEM 等 8 篇经典），然后用中文问：

“PatchCore 是怎么用 coreset 采样构建 memory bank 的？”

系统会检索出最相关的英文原文片段，交给 LLM 生成中文回答，并且每个结论都带 [1][2] 引用标注，点击可以回查原文核验——回答有据可查，而不是模型自由发挥。

二、两大核心功能

1. 中文提问，英文论文直接出答案

底层用多语言嵌入模型（paraphrase-multilingual-MiniLM-L12-v2）做跨语言检索：中文问句和英文论文段落被映射到同一个语义空间，所以“如何做异常检测”能直接命中 "anomaly detection" 的段落，不需要先翻译查询。

2. 每日 arXiv 日报，全自动

GitHub Actions 每天北京时间 09:00 自动完成：抓取 arXiv 最新 CV 异常检测论文 → LLM 中文解读（标题翻译 / 一句话总结 / 方法亮点 / 推荐评级）→ 生成日报提交到仓库。Star 之后每天来仓库看一眼 digest 目录，就能跟上领域进展。同时新论文持续进入 RAG 知识库——日报和问答共用一条供给链路。

三、系统架构

摄入链路：
PDF/TXT/MD → Loader(pypdf 抽取) → Chunker(递归分割 800/120)
           → Embedder(三级降级) → VectorStore(NumPy 余弦, 持久化)

问答链路：
中文问题 → Embedder(查询嵌入) → Retriever(BM25+稠密混合检索)
         → Generator(DeepSeek LLM) → 带引用标注的回答

四、关键技术决策

4.1 混合检索：BM25 + 稠密向量，RRF 融合

这是项目里我做得最认真的一块。稠密向量擅长语义泛化（中文问句 → 英文论文），但对专业术语（PatchCore、coreset、MVTec）的词面精确匹配是弱项；BM25 正好相反。两路排名用 RRF（Reciprocal Rank Fusion）融合——按排名而不是分数融合，天然规避两种打分量纲不可比的问题。中文分词用 CJK 字符 bigram，零分词库依赖。

我自建了一个 16 题中文评测集（scripts/eval_retrieval.py），在真实论文库上实测（8 篇经典论文 / 631 个块）：

检索模式 R@1 R@3 R@5 MRR
dense（纯向量） 0.750 0.938 1.000 0.846
bm25（纯词面） 0.875 0.875 0.875 0.875
hybrid（混合） 0.812 1.000 1.000 0.906

结论很直观：BM25 补上了术语精确匹配的短板（R@3 从 0.938 提升到 1.000），混合模式的 MRR 最高。检索优化不能凭感觉，要靠评测集说话。

4.2 为什么用 NumPy 而不是 FAISS

论文库量级小（千级块、384 维），暴力余弦一次矩阵乘法就是全库打分，延迟 <10ms，而且是精确检索。FAISS 的价值在 ANN 索引换速度，百万级向量才有意义。用 NumPy 还让全流程透明可解释——余弦相似度就是 L2 归一化后的点积，每一步都可观察、可调试。

4.3 嵌入三级降级：无网无 Key 也能跑

  1. API 嵌入：OpenAI 兼容 /embeddings 端点（配置即用）；
  2. 本地语义嵌入：fastembed + ONNX Runtime，免 torch，部署轻；
  3. 哈希兜底：词/字符 n-gram 哈希投影，纯离线（降级为词面匹配）。

降级路径本身也被测试覆盖——42 个测试全部离线运行，不下载模型、不联网，2 秒跑完。

五、工程化实践

  • 测试：42 个用例覆盖分块 / 向量库 / 嵌入降级 / BM25 / 混合检索 / 端到端 / HTTP 契约；
  • CI：push/PR 自动 lint + pytest（Python 3.10–3.12 矩阵）；
  • 增量摄入：按 source 替换旧块，重复上传不膨胀；
  • Web 服务：应用工厂 + 懒加载 + 健康探针 + 统一 JSON 错误处理；
  • 部署：Docker 一键起 gunicorn，也可 pip install 后用 CLI。

六、快速开始

git clone https://github.com/zanezhao0708/PaperMindRAG.git
cd PaperMindRAG
pip install -r requirements.txt

python scripts/download_papers.py   # 下载 8 篇经典论文
python app.py                        # 打开 http://127.0.0.1:5000

七、局限与规划

目前 PDF 只抽取文本，图表内容无法解析，后续可以引入多模态文档解析；嵌入还没有缓存，可以按 chunk 哈希做增量复用；评测集计划扩展为人工标注的多文档混合问题。
